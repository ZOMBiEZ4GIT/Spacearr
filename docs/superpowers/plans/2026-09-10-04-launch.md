> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package Spacearr the way the self-hosted community expects in 2026: a multi-arch Docker image with PUID/PGID/UMASK/TZ, CI that builds and tests every change and publishes on tags, an honest README with screenshots and a "what it does not do" section, an AI-usage disclosure, a security policy, a docs folder, and an Unraid template.

**Architecture:** One `docker/Dockerfile` (multi-stage: Node build of `/web`, .NET publish, Alpine runtime with ffmpeg + mediainfo + su-exec), an entrypoint that drops privileges, GitHub Actions for PR checks and tag releases to `ghcr.io/zombiez4git/spacearr`, and Markdown docs under `docs/`.

**Tech Stack:** Docker BuildKit, `docker/build-push-action@v6`, GitHub Actions `ubuntu-latest`, `mcr.microsoft.com/dotnet/sdk:8.0-alpine`, `mcr.microsoft.com/dotnet/aspnet:8.0-alpine`, `node:20-alpine`.

**Spec:** `docs/superpowers/specs/2026-09-10-spacearr-standalone-design.md`

## Global Constraints

- All earlier plan constraints apply. Branch `rebuild`.
- No telemetry, no update checks that phone home, no external font or CDN. The only outbound traffic is to the user's own Radarr/Sonarr.
- Image runs as the PUID/PGID user, never root, after the entrypoint chowns `/config`.
- Versioning: semver tags `vX.Y.Z`; `latest` = latest stable tag; `develop` = latest push to `rebuild`/`main`. Image labels follow OCI conventions.
- Every claim in the README must be true of the built image. No "coming soon" features.

`docker/Dockerfile`:

```dockerfile
# syntax=docker/dockerfile:1.7
FROM --platform=$BUILDPLATFORM node:20-alpine AS web
WORKDIR /web
COPY web/package.json web/package-lock.json ./
RUN npm ci --no-audit --no-fund
COPY web/ ./
RUN npm run build

FROM --platform=$BUILDPLATFORM mcr.microsoft.com/dotnet/sdk:8.0-alpine AS build
ARG TARGETARCH
WORKDIR /src
COPY global.json Directory.Build.props Spacearr.sln ./
COPY src/Spacearr/Spacearr.csproj src/Spacearr/
COPY src/Spacearr.Tests/Spacearr.Tests.csproj src/Spacearr.Tests/
RUN dotnet restore src/Spacearr/Spacearr.csproj -a $TARGETARCH
COPY src/ src/
COPY --from=web /src/Spacearr/wwwroot src/Spacearr/wwwroot
RUN dotnet publish src/Spacearr/Spacearr.csproj -c Release -a $TARGETARCH -o /app -p:SkipWeb=true -p:UseAppHost=false

FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
LABEL org.opencontainers.image.title="Spacearr" \
      org.opencontainers.image.description="The cooler looking WinDirStat for your arr stack" \
      org.opencontainers.image.source="https://github.com/ZOMBiEZ4GIT/Spacearr" \
      org.opencontainers.image.licenses="GPL-3.0"
RUN apk add --no-cache ffmpeg mediainfo su-exec tzdata icu-libs \
    && addgroup -g 1000 spacearr && adduser -D -u 1000 -G spacearr spacearr
ENV SPACEARR_CONFIG_DIR=/config SPACEARR_PORT=8787 PUID=1000 PGID=1000 UMASK=002 TZ=Etc/UTC \
    DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1 ASPNETCORE_ENVIRONMENT=Production
WORKDIR /app
COPY --from=build /app ./
COPY docker/entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh && mkdir -p /config && chown spacearr:spacearr /config
VOLUME /config
EXPOSE 8787
HEALTHCHECK --interval=30s --timeout=5s --start-period=20s CMD wget -qO- http://127.0.0.1:8787/api/v1/system/status >/dev/null || exit 1
ENTRYPOINT ["/entrypoint.sh"]
```

Note: the `web` stage's Vite config writes to `../src/Spacearr/wwwroot`, so inside the stage the output lands at `/src/Spacearr/wwwroot`; the `COPY --from=web` path above reflects that.

`docker/entrypoint.sh`:

```sh
#!/bin/sh
set -e
PUID="${PUID:-1000}"; PGID="${PGID:-1000}"; UMASK="${UMASK:-002}"
if [ "$(id -u)" = "0" ]; then
  if [ "$(id -g spacearr)" != "$PGID" ]; then groupmod -o -g "$PGID" spacearr 2>/dev/null || sed -i "s/^spacearr:x:[0-9]*:/spacearr:x:$PGID:/" /etc/group; fi
  if [ "$(id -u spacearr)" != "$PUID" ]; then usermod -o -u "$PUID" spacearr 2>/dev/null || sed -i "s/^spacearr:x:[0-9]*:[0-9]*:/spacearr:x:$PUID:$PGID:/" /etc/passwd; fi
  chown -R "$PUID:$PGID" /config 2>/dev/null || true
  umask "$UMASK"
  echo "Spacearr starting as uid=$PUID gid=$PGID umask=$UMASK tz=${TZ}"
  exec su-exec "$PUID:$PGID" dotnet /app/Spacearr.dll
fi
umask "$UMASK"
exec dotnet /app/Spacearr.dll
```

Alpine has no `usermod`; the `sed` fallbacks handle it. `shadow` could be installed instead, but the sed approach keeps the image small and is what several arr companions do.

`README.md`:

```markdown
# Spacearr

**The cooler looking WinDirStat for your arr stack.**

Spacearr scans the media library behind Radarr and Sonarr and draws it as a treemap: block size is bytes, colour is bitrate heat. Hover to see what a block is, click to see the file facts, and reclaim space through the arr apps' own APIs. Nothing leaves your network.

![Library view](docs/screenshots/library-dark.png)

## What it does

- **Treemap of your whole library.** Movies as blocks, series → season → episode drill-down, posters under the heat colour on large blocks.
- **Bitrate heat.** Colour by bits per pixel per frame, normalised per codec, so a 6 GB HEVC file and a 12 GB x264 file that look the same are coloured the same. Relative mode ranks within your library; absolute mode uses fixed thresholds.
- **Any number of Radarr and Sonarr instances.** The 1080p + 4K two-instance setup is the normal case, and Spacearr shows what it costs.
- **Duplicates across instances**, ranked by wasted bytes, with a keep-this-one action.
- **Two actions, preview first.** Delete, or replace with a smaller release (change the quality profile, delete, search). Every preview lists exactly what will be asked of the arr app and how many bytes it frees. Confirmation is never one click.
- **Nothing leaves your network.** Posters are proxied from your arr app. No fonts, analytics, or update checks call out.

## What it does not do

- It does not transcode. If you want to re-encode files in place, use Tdarr, Unmanic or FileFlows. Spacearr keeps the release and lets the arr app fetch a smaller one.
- It does not delete from disk itself. Deletions go through Radarr/Sonarr so they stay in sync.
- It does not talk to Plex, Jellyfin or Emby, and it does not know what has been watched. Maintainerr and Janitorr do that.
- It has no rules engine and never acts on its own. Every action is a person clicking a preview and then a confirm.

## How heat works

`bpp = video bitrate ÷ (width × height × frame rate)`, divided by a codec factor (x264 1.0, HEVC 0.6, AV1 0.5, VP9 0.65, MPEG-2 1.5, VC-1 1.2). Relative mode colours by percentile in the current view; absolute mode maps 0.04 → green through 0.30 → red. Details in [docs/heat.md](docs/heat.md).

`SECURITY.md`:

```markdown
# Security

Spacearr stores API keys for your Radarr and Sonarr, so it is a credential store and is treated as one.

- Authentication is mandatory on every route except the version/status endpoint. A test enforces this in CI.
- Arr API keys are encrypted at rest (AES-256-GCM, key in `/config/secret.key`, mode 0600) and are never returned by the API.
- Five failed sign-ins per minute per address lock that address out for a minute.
- The container runs as the PUID/PGID user, not root.

**Reporting.** Email roland.taylor@workweargroup.com.au with "Spacearr security" in the subject, or use GitHub's private vulnerability reporting on this repository. You will get a reply within 72 hours. Please do not open a public issue for a vulnerability.
